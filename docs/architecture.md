# 一个仓库，四个端

共享同一账号、插件协议、词汇进度和业务 API，避免为不同端复制核心逻辑。

| 目录 | 负责内容 | 运行环境 |
|---|---|---|
| `src/`、`public/` | React 界面；网页端及两个客户端的共享界面 | 浏览器 / Electron / Capacitor |
| `clients/desktop/` | 托盘、窗口、更新、离线、Mihomo、壁纸、独立网盘窗口 | Windows / Electron |
| `android/` | 原生播放、通知、控件、离线、VPN、动态壁纸及网盘窗口 | Android 6+ / Java 21 / SDK 35 |
| `server/` | FastAPI、SQLite、鉴权、插件、资产和媒体 API | Python 3.11+ |
| `deploy/` | Nginx、systemd 配置 | Linux |
| `website/` | 独立官网的静态页面源文件 | GitHub Pages |
| `third_party/` | 必要的第三方脚本、许可证和来源 | 构建输入 |

`website/` 的部署目标仍为独立官网仓库；应用源码只推送到 `liveldy/dawnbreaker-app`。不需要额外拆出网页仓库或多份客户端界面。

服务端默认 7779；网页开发及生产入口默认 7780。7778 不属于本项目。

账号鉴权由服务端执行，插件安装仅开启相应账号能力。所有写入需在线；客户端缓存支持只读文档、卡册、天眼和已缓存音乐。听曲记录带幂等 ID，联网补发，不能通过重复同步领取奖励。代理和壁纸仅在设备端运行；云端壁纸发布由服务端核验管理员权限。

API 密钥与订阅使用服务端独立加密密钥；暗格以用户主密码在客户端加密。源码仓库不包含数据库、真实配置、会话、密钥或部署凭据。
