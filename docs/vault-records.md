# 暗格资料类型

暗格提供密码、卡包、个人信息册三类记录。卡包适合银行卡、信用卡、会员卡等号码资料；个人信息册可保存证件、联系方式、地址和单位。每种记录都支持备注和自定义字段，敏感字段默认隐藏。搜索在本机解锁后的资料中进行，列表只显示敏感号码的末四位。

三类记录使用同一份加密信封：PBKDF2-SHA256（600000 次）派生主密钥，AES-256-GCM 加密，账号 ID 用作附加认证数据。主密码和明文不发送到服务端，服务器仍只接收加密内容与版本号。保留 `dawn-vault-v1` 标记，1.4.5 以 `schema:3` 兼容旧记录；旧记录自动识别为密码，已有字段保持不变。无法识别的类型或损坏数据不会被覆盖。

复制、编辑、删除、加密保存与导出均在解锁后进行。可导出当前分类或全部记录，支持 JSON 和 CSV；导出为用户主动保存的明文文件。离开页面或闲置 10 分钟自动锁定。跨设备编辑冲突仍使用原有版本检查，禁止静默覆盖。

1.4.5 的照片保存于加密明文对象内部，不通过公开图片接口上传，不使用远程图片 URL。`photos.front` / `photos.back` 保存卡片两面；自定义字段的 `kind` 可为 `text` 或 `photo`，后者使用 `photo` 对象。照片对象为原始文件名与 PNG / JPEG / WebP 的 data URL。前端检查文件签名、大小及实际解码能力，原文件字节不压缩、不裁切；每张最多 5 MiB，含 base64 的整个解密对象最多 32 MiB。照片名称可以参与本机搜索，图片编码不会参与搜索。JSON / CSV 导出包含照片对象，单张下载恢复原始二进制；Android 使用系统文件保存窗口，不申请全盘访问权限。

新信封声明 `format_version:3`，旧信封默认 2。服务器禁止以更低格式版本覆盖已有新版信封，同时保留原有乐观版本锁，防止旧客户端丢失照片种类。Pydantic、HTTP 中间件和 Nginx 仅为暗格路径提高密文请求上限，其他插件的限制不变。服务端仍无法解密照片与资料。
